# AI strength evaluation

Standing record of PebbleGo engine strength. **Update this file after every
engine change**: run the ladder, append a row to the history table and to
`tools/eval/results.jsonl`.

## Method

- Our engine plays as a GTP engine via `tools/eval/gtp.js` (loads the real
  `src/pkjs/pebble-js-app.js`, synchronous, no pondering).
- Matches run with `tools/eval/gtp_match.js`: independent referee
  (`tools/eval/go_rules.js`), 9x9, komi 7.5, 2 consecutive passes end the
  game, Chinese area scoring with Benson dead removal. Illegal move =
  immediate loss. SGFs saved under `tools/eval/sgf/<label>/`.
- Ladder rungs weakest-first via `tools/eval/ladder.js`
  (`node tools/eval/ladder.js --games 4 --rungs 0,1,2`).
- Opponents: KataGo v1.17.1 Eigen-AVX2 (CPU) with weak nets
  (`kata1-b6c96`, `kata1-b10c128`) at capped `maxVisits`; GNU Go 3.8 levels
  0/3/10 (`--capture-all-dead --chinese-rules --positional-superko`).
- Dumbest rung: `tools/eval/random_gtp.js` (uniform-random legal moves).
- Dummy-off (which dummy is weaker): GNU Go-0 vs KataGo b6-v1 in the same
  runner, 4 games, alternating colors.
- Raw JSON log: `tools/eval/results.jsonl` (git-ignored run log; the tables
  in this file are the curated record).
- Note: engine uses its own fixed search budget; `time_settings`/`time_left`
  are accepted by the adapter but ignored (fine for untimed ladder games,
  must be fixed before CGOS 5-min games).

## Vendor setup (git-ignored binaries/models)

`tools/eval/vendor/` is git-ignored. Recreate it with:

```sh
mkdir -p tools/eval/vendor
cd tools/eval/vendor

# KataGo CPU engine (Eigen AVX2 build; v1.15.3 needs libssl1.1, avoid it)
curl -sL -o katago-v1.17.1-eigenavx2.zip \
  https://github.com/lightvector/KataGo/releases/download/v1.17.1/katago-v1.17.1-eigenavx2-linux-x64.zip
python3 -c "import zipfile,os; zipfile.ZipFile('katago-v1.17.1-eigenavx2.zip').extractall('katago171'); os.chmod('katago171/katago',0o755)"
./katago171/katago version   # expect "KataGo v1.17.1 ... Using Eigen(CPU) backend"

# Weak nets (ladder rungs, weakest first)
curl -sL -o kata1-b6c96-s175395328-d26788732.txt.gz \
  https://media.katagotraining.org/uploaded/networks/models/kata1/kata1-b6c96-s175395328-d26788732.txt.gz
curl -sL -o kata1-b10c128-s41138688-d27396855.txt.gz \
  https://media.katagotraining.org/uploaded/networks/models/kata1/kata1-b10c128-s41138688-d27396855.txt.gz
# Stronger 9x9 specialist (top rungs, fetch when needed):
# https://media.katagotraining.org/uploaded/networks/models_extra/kata9x9-b18c384nbt-20231025.bin.gz

# GNU Go baseline
sudo apt-get install -y gnugo   # expect GNU Go 3.8
```

Per-rung KataGo configs (`rung_<net>_<visits>.cfg`) are generated by
`tools/eval/ladder.js` from `katago171/default_gtp.cfg` (strip the
`maxVisits`/`numSearchThreads`/`ponderingEnabled` lines, append the rung
override). Net catalogue: https://katagotraining.org/networks/ and
https://katagotraining.org/extra_networks/.

## Diagnosis (from 12 scored games + SGF replay)

- Capture asymmetry is ~50-to-0 against us in every game (e.g. game0 vs b6:
  we lost 55 stones, took 0; vs GNU Go 10: lost 54-55, took 3-4). The engine
  essentially never captures anything while losing every group it puts down.
- Self-play scores (W+4.5, W+8.5) are misleading: both sides share the same
  blindness, so games look sane. External games expose it.
- Working hypothesis: the veto/danger stack (self-atari veto, snapback
  guard, wall-density penalty, ladder-escape verdicts) suppresses nearly all
  contact/capturing moves, while the search cannot read opponent threats —
  so we feed stones into dead fights and never start a winning one. To be
  verified by SGF review + atari-rate metrics (see next steps).
- Adapter control is clean (self-game W+18.5, no illegal moves anywhere),
  so the losses are genuine engine weakness, not harness artifacts.
- Observation: one self-game never reached 2 passes in 300 moves — possible
  endgame pathology (both sides refusing to agree the game is over). Watch
  for recurrence; consider a move-cap adjudication rule in the runner.
